V9's Back workaround is scoped to AnkiDroid. At HTML load it inspects the private
WebViewClient -> fragment/lazy/viewmodel ownership graph, bounded to six levels
and 512 objects, looking only for NanoHTTPD's ServerSocket. It recognizes the
original NanoHTTPD class name and the verified R8 name 'bv' in this exact APK.
It skips static fields and does not change card data, collection or preferences.
If found, it sets a 500 ms accept timeout once per socket and starts one background
loopback connection to release any accept that began with an infinite timeout.
The wakeup carries no HTTP body. Normal socket/client cleanup and thread joining
remain in place. This is intended to let NanoHTTPD.stop() complete despite the
failed AsynchronousCloseMonitor signal handler. The causal diagnosis and the
workaround's effectiveness on iPad are not yet confirmed. V8's failed-accept
handler can additionally delay an expected timeout by 250 ms.

New logs show whether the listener was found/configured and awakened, and whether
activity stop and destroy returned. If reflection or wakeup fails, the workaround
logs that failure and leaves normal lifecycle behavior in place. The actual
private-field layout and native socket behavior still require device testing.

For Image Occlusion:
- Log up to eight images' complete/natural/client dimensions and URL schemes,
  plus up to four canvas dimensions, after question/answer rendering. Filenames,
  image bytes, card text and credentials are not logged.
- Log image-response status, MIME and byte count from Android's resource handler.
- If a local GET is unhandled, return 404 directly. AnkiServer already rejects
  GET with 404; this avoids forwarding a missing media GET to its socket path
  and lets the browser finish the image request instead of waiting indefinitely.
These changes diagnose missing/broken images and canvas sizing. They do not claim
to repair Image Occlusion or download missing media. A small affected .apkg with
media is still useful for reproducing the actual card template.
