V6's report confirms every known reviewer asset was read from the APK, but the
final inline 'Husk reviewer ready' console probe is absent and _showQuestion is
still missing. Memory stays around 4 GB; no native fatal signal is recorded.
WhiteboardFragment is created. Back finishes the reviewer and resumes DeckPicker
internally, but the user reports an unresponsive screen and whiteboard controls.

Two changes:
1. Apply current WebView settings before loadUrl, postUrl, loadData and
   loadDataWithBaseURL submit a native load. Previously setters posted a deferred
   update, while creating a WebView immediately submitted the default JavaScript
   value (false). AnkiDroid enables JavaScript and loads its page in the same call
   stack. WebKit can start navigation before the deferred enable arrives. V7
   submits the settings first. Explicit JavaScript=false is still honored;
   JavaScript is not globally forced on. The host regression fails on v6 and
   passes on v7, including disabled JavaScript and destroyed views. iPad WebKit
   behavior is not yet verified. The absence of script execution on v6 fits this
   ordering bug, but does not prove it is the only remaining cause.
2. For com.ichi2.anki only, a visible laid-out new-reviewer WhiteboardView or
   WhiteboardToolbar routes touches through Android instead of directly to
   WebKit. The native WebView previously took all touches in its rectangle even
   when these Android controls occupied that same window. Hiding/removing the
   whiteboard restores normal WebKit input. Host geometry/name fixtures verify
   this gate; they do not test drawing, actual touch delivery or iOS Pencil data.
   Page scrolling/links intentionally do not receive native touches while the
   whiteboard overlay is visible.

Back freeze remains unresolved. V7 adds logs for native WebView frame visibility,
touch eligibility and destruction. They help distinguish stale native page/input
state from a different deck-list rendering or lifecycle failure. No separate
Back fix is claimed. The earlier native socket/memory crash is also unchanged.
