V8 changes:
1. NanoHTTPD's listener catches IOExceptions and immediately retries, logging
   only at FINE level. V8 enables that level on its logger and installs a handler
   that logs the first three failed accepts, then every hundredth, and sleeps
   250 ms on that listener thread after each such failure. Successful accepts
   are not delayed. Other apps and unrelated logger levels are unchanged.
   This bounds a suspected allocation-heavy retry loop; it does not repair the
   native socket implementation. The exact socket error and effectiveness on
   the iPad remain to be confirmed. Logger name 'bv' is verified for this exact
   official AnkiDroid 2.26.0alpha6 APK; unobfuscated NanoHTTPD is also supported.
2. For AnkiDroid HTML with an exact http://127.0.0.1:<port>/ base, register that
   origin with Husk's existing WebKit scheme mapping. Relative reviewer GETs
   now reach AnkiDroid's shouldInterceptRequest handler, which already serves
   MathJax and media from assets/files. Previously these went directly to the
   local HTTP listener. MathJax's pending script load can block _showQuestion's
   render queue; whether that explains this card is unverified. POST backend
   calls can still depend on the actual local HTTP server.
3. After _showQuestion/_showAnswer calls, log DOM state after 1.5 and 6 seconds:
   qa existence, text/HTML length, opacity, MathJax state and scheme. No card
   text or credentials are logged. Internal /_anki/ resource requests are logged.
